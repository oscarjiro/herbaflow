# Herbaflow frontend

React 19 + TypeScript, built with Vite and run with `pnpm`. It drives the 8-stage
plant-compound-disease-target pipeline: setup, per-stage review and approval, interactive result
charts, and result export. State and data-fetching use TanStack Query; routing uses TanStack Router;
tables use TanStack Table; styling is Tailwind v4 with `hf-*` design tokens. Charts use Plotly
(dot/bar), cytoscape (network graphs), and upsetjs (overlap). Forms use react-hook-form with Zod.

## Directory map (canonical homes)

- `src/api/` **GENERATED, do not hand-edit.** `types.gen.ts`, `sdk.gen.ts`, `client.gen.ts`,
  `zod.gen.ts`, and the `@tanstack/` query-option helpers are produced by `@hey-api/openapi-ts` from
  `../backend/openapi.json`. Regenerate with `pnpm gen:api`; never write wire types by hand.
- `src/routes/` TanStack Router file routes (`analysis.$id.$stage.tsx`, `analysis.$id.tsx`, `about.tsx`,
  `__root.tsx`, ...). `routeTree.gen.ts` is generated by the router plugin, not edited by hand.
- `src/components/` shared UI. `components/stages/` holds the per-stage views (`Stage1View`..`Stage8View`)
  plus the shared stage pieces (`ApprovalBar`, `ParamPanel`, `StageNotApplicable`, `ProvidedByYouBadge`,
  `StageRunningSkeleton`, ...). `components/charts/` holds the chart wrappers.
- `src/contract/` the analysis contract loader and the display-label home (`labels.ts`): one place that
  maps entity/stage ids to human-readable names.
- `src/hooks/` React hooks (`useParamRedo`, `useResetFrom`, `useStageEntityEdit`, `useAddWithDedup`,
  `useEntityCatalog`, `useAnalysisStatus`, ...).
- `src/lib/` pure helpers with no React (`metricInfo`, `format`, `csv`, `download`, `ctpGraph`,
  `chartExport`, `chartTheme`, `runStatus`, `pageMeta`, `problem`, `stp`, ...).
- `src/features/` feature-scoped modules (for example `landing/`).
- `src/types/` ambient module declarations for untyped deps (`plotly.d.ts`, `react-cytoscapejs.d.ts`).
- `src/test-utils/` shared test helpers.
- `src/index.css` the single stylesheet: `hf-*` design tokens plus component recipes and the glass system.

## Non-negotiable conventions

- **Wire types are generated, never hand-written.** Everything under `src/api/**` and `routeTree.gen.ts`
  is codegen output. If the backend contract changes, run `pnpm gen:api` and commit the regenerated
  files. The codegen drift gate (`python scripts/check_codegen_drift.py`) fails the build if they are stale.
- **`hf-*` design tokens are the single source for color, surface, border, and spacing.** They are CSS
  custom properties (`--hf-bg`, `--hf-surface`, `--hf-sage`, `--hf-terracotta`, `--hf-neutral-*`, ...)
  defined in `index.css` and consumed through Tailwind v4. Do not hardcode raw hex values in components.
- **`index.css` component recipes MUST live inside `@layer components`.** Tailwind's `utilities` layer is
  ordered after `components`, so a recipe written outside a layer wins over utility classes and breaks
  overrides. Keep every component recipe (including the glass recipe) in the `@layer components` block.
- **One canonical home per concern; reuse before you add.** Extract shared logic once and import it, never
  copy-paste a second variant. Existing homes to reuse: metric/tooltip copy lives in `lib/metricInfo.ts`;
  the param-redo mutation lives in `hooks/useParamRedo.ts`; the "not applicable" stage panel is
  `components/stages/StageNotApplicable.tsx`; the "provided by you" marker is
  `components/stages/ProvidedByYouBadge.tsx`; display labels live in `contract/labels.ts`; CSV building
  lives in `lib/csv.ts`; run-status derivation lives in `lib/runStatus.ts`.
- **Errors follow the backend RFC 9457 problem shape.** Parse and surface them through `lib/problem.ts`.

## Tests

- **Component and unit tests are colocated** as `src/**/*.test.tsx` (or `.test.ts`) next to the code they
  cover. This is where most frontend tests live.
- **Integration tests live in the flat `frontend/tests/` folder** (`SetupView`, `Stage2View`, `Stage3View`,
  `contract`, `staticSeo`, `indexHtml`, `lint-danger`), alongside the shared MSW handlers (`handlers.ts`),
  the router test helper (`renderWithRouter.tsx`), and the Vitest setup (`setup.ts`). There are no
  `unit/`, `integration/`, or `e2e/` subfolders.
- Run everything with `pnpm test` (`vitest run`); add `--coverage` for a report. Mock the API layer with
  MSW (`frontend/tests/handlers.ts`); mock cytoscape in unit tests (jsdom has no canvas). End-to-end
  behavior is verified manually against a running stack, not by a committed frontend E2E suite.

## Gates (must be green to merge)

- `pnpm typecheck` (`tsc --noEmit`, strict), `pnpm lint` (eslint), `pnpm format:check` (prettier),
  `pnpm test` (vitest), and the codegen drift gate (`python scripts/check_codegen_drift.py`).
